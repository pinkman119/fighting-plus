# fighting-plus 需求文档（v1.0 已确认）

> 基于三轮需求拷问（grilling）整理，已于 2026-11-18 确认。
> 对应 OpenSpec 变更：`openspec/changes/shared-tactical-board-mvp/`

## 1. 产品定位

**fighting-plus** 是面向三角洲行动/塔科夫类撤离射击游戏三人小队的实时共享战术板桌面软件。队员将拿到的敌方信息标注在共享地图上，实时同步给队友，解决"看到了但说不清在哪"的信息传递问题。

## 2. 核心决策汇总

| 决策项 | 结论 |
|---|---|
| 目标游戏 | 三角洲行动类撤离游戏（3人小队），不硬绑定游戏，任何地图截图可用 |
| 软件形态 | Electron 桌面应用 + **透明置顶 Overlay**（不注入游戏进程，零封号风险，要求游戏以无边框窗口模式运行） |
| 前端框架 | Vue 3 |
| 地图来源 | 用户上传图片（无内置官方地图） |
| 身份体系 | 账号系统（注册/登录，邮箱+密码） |
| 房间人数 | 上限 **6 人**（适配不同游戏队伍规模） |
| 编辑权限 | 三人均可标注；任何成员可上传地图 |
| 标记时效 | 显示"X秒前"时间戳 + 随时间自动变淡（不自动删除），支持手动移除 |
| 房间沟通 | 仅标注同步，不做聊天/语音 |
| 部署 | 公网服务器，开发者自行运营 |
| 历史 | 账号体系下保存历史局，可回看 |
| 服务端技术栈 | Node.js + NestJS（Socket.IO 实时通道，PostgreSQL 持久化） |

## 3. 功能需求

### 3.1 账号系统（user-auth）

- FR-01: 邮箱+密码注册、登录（密码 bcrypt 加密存储），JWT 会话（access 2h + refresh 7d）
- FR-02: 昵称（非空 ≤16 字符）、预置头像选择

### 3.2 房间系统（room-management）

- FR-03: 房主创建房间，生成唯一邀请码；成员凭码加入，**上限 6 人**
- FR-04: 房间成员列表实时显示在线状态；断线 10 秒内标记离线，重连恢复；成员入房分配房间内唯一标识颜色
- FR-05: 房主可移交房主权限给在线成员
- FR-06: 房主可手动归档；全员离线 30 分钟自动归档；归档生成对局快照

### 3.3 共享战术板（tactical-board，核心）

- FR-07: **任何成员**可上传地图图片（jpg/png/webp，≤10MB），全房间同步换图
- FR-08: 画布支持滚轮缩放（10%–400%）与拖拽平移，仅影响本地视图
- FR-09: **点标记**：敌人位置图标、敌人数量的文字备注，附创建时间戳与创建者颜色
- FR-10: **箭头/路线**：拖拽绘制进攻/撤退/搜索方向
- FR-11: **区域圈选**：圆形/矩形半透明区域（危险区/搜索区/落点区）
- FR-12: **编辑控制**：撤销/重做（本地栈）、橡皮擦删除、一键清空（本地二次确认，清空可整批撤销恢复）
- FR-13: **标记时效**：显示"X秒前"，0–30 秒完全不透明，之后逐渐变淡，5 分钟降至 30% 并保持；不自动删除，可手动移除
- FR-14: **实时同步**：标注操作经服务端统一编号排序广播，端到端 <500ms；每个标注以创建者专属颜色渲染
- FR-15: **断线重连**：重连后拉取全量快照（地图+存活标注+成员）重建画布，保证状态一致

### 3.4 Overlay 模式（overlay-mode）

- FR-16: 全局热键（默认 Alt+Q，可配置）呼出/隐藏半透明置顶战术板，无需切出游戏
- FR-17: 点击穿透可切换：穿透态仅展示，非穿透态支持删除单个标注
- FR-18: Overlay 复用主画布组件，锁定查看模式（隐藏编辑工具栏）
- FR-19: 首次使用引导：提示游戏需以"无边框窗口"模式运行（全屏独占下 Overlay 不可见）
- **安全红线**：绝不注入游戏进程、不读取游戏内存

### 3.5 历史记录（match-history）

- FR-20: 归档时保存对局快照（名称、地图、成员及颜色、标注最终状态、起止时间）
- FR-21: 历史局列表（按结束时间倒序，仅本人参与的对局）
- FR-22: 历史局只读回看：按原颜色渲染标注快照，支持缩放平移，不可编辑

## 4. 非功能需求

- NFR-01: 服务端 Node.js + NestJS，Socket.IO 实时通道，PostgreSQL + Prisma 持久化
- NFR-02: 单房间 ≤6 人、低频标注；初期支持 ~200 并发房间（预留 Socket.IO redis adapter 水平扩展）
- NFR-03: 强制 HTTPS/WSS；上传文件类型嗅探校验；接口限流
- NFR-04: 客户端 Electron + Vue 3 + Konva 画布，首版仅 Windows
- NFR-05: 断线重连后状态一致性（全量快照 + 增量事件，服务端单一事实源）

## 5. 明确不做（本期范围外）

- ❌ 注入式 Overlay（ACE 反作弊封号风险）
- ❌ 语音/文字聊天
- ❌ 读取游戏内存/自动定位敌人
- ❌ 内置官方地图
- ❌ macOS / Linux 支持
- ❌ CRDT 协同算法（规模内用服务端顺序 + 最后写入胜）
